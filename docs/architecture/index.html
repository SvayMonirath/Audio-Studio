Audio Studio System Overview & ADRs

A self-contained platform for evaluating, scoring, and comparing speech synthesis (TTS) and speech recognition (ASR) machine learning models for the Khmer language.

1. What Audio Studio Does

Audio Studio solves a specific problem in speech machine learning research: evaluating how well speech models pronounce words and recognize natural human speech. Automated metrics (such as Word Error Rate or acoustic loss numbers) do not accurately reflect whether a computer-generated voice sounds natural or mispronounces tone and syllables in Khmer.

The platform provides two primary interfaces that communicate with a single Python standard library backend and a local SQLite database:

Admin & Researcher Portal

Path: public/admin.html

  • Study Creator: A 4-step wizard to upload WAV audio files, match transcripts via CSV, assemble modular test components on an interactive canvas, and launch evaluation campaigns.
  • Active Studies: Manage live evaluation studies, inspect evaluator completion rates, toggle study status, or delete campaigns.
  • Results & Analytics: Compute Mean Opinion Scores (MOS) with 95% confidence intervals, rater consensus agreements, and export full CSV audit ledgers.

Rater & Evaluator Portal

Path: public/eval.html

  • Frictionless Registration: Evaluators enter their name or pseudonym; no account or password creation required.
  • Audio Waveform Deck: Interactive 76px waveform canvas with playback scrubbing, speed controls (0.8x, 1.0x, 1.2x), and telephone call audio simulation (8 kHz bandpass filter).
  • Hold-and-Drag Defect Tagging: Listeners drag across the waveform or click Khmer word pills to flag mispronunciations, awkward pauses, and robotic buzzes.
  • Listening Verification: Evaluators type what they actually heard to generate real-time visual text diffs against expected transcripts.

3. Architectural Decision Records (ADRs)

ADR-01 Zero Third-Party Python Dependencies Accepted Invariant

Decision: The backend must run completely on Python's built-in standard library without installing packages via pip.

Rationale: Audio Studio is an academic thesis and research platform. Avoiding third-party dependencies eliminates dependency drift, broken virtual environments, C-extension build failures, and security vulnerabilities. Any computer with Python 3.8+ can clone the repository and run python3 run_server.py in under two seconds.

ADR-02 Single-File Local SQLite Persistence with Enforced Foreign Keys Accepted Invariant

Decision: Use a local SQLite file (workbench.db) with PRAGMA foreign_keys = ON; and parameterized SQL queries.

Rationale: Academic evaluations require absolute data durability without managing separate database servers (PostgreSQL or MySQL). SQLite commits transactions directly to the local solid-state drive with full ACID reliability. Deleting a test campaign automatically cascades to remove related evaluations and defect tags cleanly.

ADR-03 Cloudflare Tunnel Outbound Host Ingress for $0 Zero-Risk Public Hosting Accepted Invariant

Decision: Expose the local server to public evaluators using Cloudflare Tunnel (via run_server.py --share) rather than deploying to free cloud containers (such as Render or Koyeb).

Rationale: Free cloud container tiers use ephemeral filesystems that erase all local file changes when an idle instance sleeps. Hosting on a local machine via Cloudflare Tunnel guarantees that the SQLite database and physical WAV audio files are never wiped, requires no credit card, and eliminates 50-second cold-start connection timeouts.

ADR-04 HTTP 206 Partial Content Range Streaming for Audio Assets Accepted Invariant

Decision: Implement native byte-range parsing in run_server.py to support HTTP Range: bytes=start-end headers.

Rationale: Modern desktop and mobile browsers require HTTP 206 Partial Content responses to scrub through audio timelines and calculate duration metadata before the entire file finishes downloading. Without range request support, mobile browsers stall when loading uncompressed WAV audio.
