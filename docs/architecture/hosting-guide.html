$0 Free Hosting & Cloudflare Tunnel Guide

A comprehensive operational runbook for deploying Audio Studio publicly at zero cost without risk of database data loss or cloud overage fees.

1. Why Free Cloud PaaS Wipes Evaluation Data

Standard free cloud platforms (Render, Koyeb, Railway, and free-tier Hugging Face Spaces) are designed for stateless applications. Their free tiers run inside virtual containers with ephemeral filesystems:

Free Cloud PaaS Behavior

  • When no evaluator visits for 15 minutes, the server enters sleep mode to save compute.
  • When a new visitor arrives, the platform starts a fresh container from the original Git repository commit.
  • Fatal Result: Any changes written to workbench.db (all rater scores) and newly uploaded audio files in audio/uploads/ are permanently destroyed.

Cloudflare Host Tunnel Solution

  • The server runs on your local workstation, lab desktop, or campus PC.
  • workbench.db commits writes directly to your local solid-state drive (NVMe/SSD).
  • Result: Zero data loss. All evaluations are permanently saved on your drive, even if the tunnel restarts.

2. Step-by-Step Hosting Runbook

Operational Mode: Quick Public Tunnel (Instant Share)
Recommended

Use this mode to launch an immediate public evaluation link for testing cohorts without setting up domain records or Cloudflare accounts.

1

Open Terminal in repository root:

cd /Users/sorpheatepy/CADT/year-3/capstone/Audio-Studio
2

Launch the server with Mac sleep disabled:

caffeinate -d -i -m -s python3 run_server.py --port 8080 --share

caffeinate prevents macOS from entering sleep mode while your laptop lid remains open.

3

Distribute the link to evaluators:

The terminal will display a public HTTPS URL:

PUBLIC SHAREABLE LINK: https://[assigned-words].trycloudflare.com/eval

Send https://[assigned-words].trycloudflare.com/eval.html to your evaluators.

3. Permanent Free Custom Domains

Quick tunnels generate a new random URL if the server is stopped and restarted. To give your evaluators a permanent, fixed web address (such as audiostudio.yourdomain.com), follow these steps:

Step Platform Execution Details
1. Obtain Free Domain DuckDNS or is-a.dev Register a free subdomain (e.g. audiostudio.duckdns.org or audiostudio.is-a.dev). No credit card required.
2. Create Cloudflare Account dash.cloudflare.com Sign up for a free Cloudflare account with your email. Select the Free tier ($0).
3. Create Named Tunnel Zero Trust Dashboard Navigate to Networks → Tunnels → Create Tunnel. Name it audio-studio.
4. Route Hostname Public Hostname Settings Set domain to your subdomain and point the service to http://localhost:8080.

4. Continuous Integration (CI) Workflow

A GitHub Actions workflow is configured in .github/workflows/ci.yml. Whenever code is pushed to main or development, GitHub automatically runs two verification gates:

Gate 1: Automated Unit Tests

Command: python3 -m unittest discover -s tests -v

  • Runs 24 automated unit tests in an ephemeral in-memory database in ~1.4 seconds.
  • Tests database seed integrity, API endpoints, audio range requests, rater submissions, and admin authentication.

Gate 2: Package Integrity Validator

Command: python3 scripts/validate_package.py

  • Ensures all 23 core files exist and are UTF-8 readable.
  • Verifies that zero third-party dependencies have been introduced.
  • Validates all 20 benchmark test scenarios.

5. Database Snapshot & Backup Runbook

During live evaluation studies, perform regular database backups using SQLite's online backup API to prevent accidental data corruption: 

# Create a dated snapshot of workbench.db while server is running:
sqlite3 workbench.db ".backup backup_$(date +%Y%m%d_%H%M%S).db"

# Export human-readable SQL dump:
sqlite3 workbench.db .dump > workbench_dump.sql
