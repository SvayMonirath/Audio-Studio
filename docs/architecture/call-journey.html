Request Lifecycles & Data Journeys

Chronological execution pathways, step timing budgets, and failure handling across client, tunnel, server threads, and the SQLite database.

Journey 1: Evaluator Scoring & Defect Submission Flow

Triggers when an evaluator selects Likert scores, highlights mispronounced words or waveform defect regions, types perceived speech differences, and clicks Submit & Next on eval.html.

Step Timing Budget Subsystem Concrete Operation & Failure Mode
Step 1 < 5 ms eval_app.js:1540 Gathers form inputs, Likert ratings, and defect regions into payload. Fails with UI warning if required scale is empty.
Step 2 15 - 40 ms Cloudflare Tunnel Encrypted transit over outbound TLS socket. Fails with HTTP 502 if local host computer is asleep.
Step 3 < 2 ms run_server.py:976 Extracts JSON body, checks payload validity, and generates unique evaluation ID (eval-[timestamp]-[hash]).
Step 4 4 - 8 ms database.py:124 Executes parameterized INSERT into evaluations table. Uses executemany for defect regions. Rolls back cleanly if foreign key is invalid.
Step 5 10 - 25 ms HTTP Response Sends HTTP 201 with {"success": true, "id": "..."}. Frontend automatically navigates to next audio item.

Journey 2: HTTP 206 Partial Content Audio Range Streaming

Triggers when a listener loads an audio sample, drags the playhead, or auditions an acoustic defect slice. Modern browsers require byte-range requests to support instant seeking without downloading the whole audio file first.

Phase HTTP Request / Response Physical Code Execution & Header Structure
1. Client Initial Probe GET /audio/model_a/KH01.wav
Range: bytes=0-		 Browser requests initial audio header to inspect sample rate (22050 Hz / 44100 Hz) and compute duration.
2. Server Range Parse run_server.py:175-220 Server reads physical file on disk (os.path.getsize), parses byte range, opens binary file, and seeks to byte offset.
3. Partial Content Delivery HTTP/1.1 206 Partial Content Sends headers:
Content-Range: bytes 0-1048575/2458920
Accept-Ranges: bytes
Content-Type: audio/wav
4. Timeline Scrubbing Range: bytes=1200000-2400000 When rater drags playhead to middle of waveform, browser requests only the targeted slice, preventing playback buffer stalls.

Journey 3: Study Creation, CSV Matching & Canvas Serialization

Triggers in admin.html when a researcher defines a study, uploads audio and paired transcripts, customizes UI components, and launches a campaign.

File Reconciliation Logic

Source: public/js/admin_app.js:1060

  • Filename Normalization: Strips folder paths and extensions (e.g., KH01.wav → kh01).
  • Safe Pairing: Matches CSV transcript rows against uploaded audio items by exact filename, stem, or prefix.
  • Pending CSV Buffer: If CSV is uploaded before audio files, rows are buffered in memory and matched automatically when audio files arrive.

Modular UI Config Serialization

Source: public/js/admin_app.js:2560

  • Canvas Block Array: Serializes playground components (Audio Player, Prompt Text, Word Tagger, Rubric, Transcription) into ui_config_json.
  • Dynamic Presentation: Stores font size (24px/32px/40px), blind-gating blur state, and default defect error codes.
  • Database Persistence: Saved directly to campaigns.ui_config_json in SQLite for 1:1 runtime rendering in eval.html.
