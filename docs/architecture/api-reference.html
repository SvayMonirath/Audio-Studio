REST API Reference & Endpoint Contracts

Complete technical specification of all HTTP routes implemented in run_server.py, including payload schemas, required headers, and physical code locations.

1. Authentication & Boundary Policy

Access Tier Authentication Mechanism Target Endpoints & Purpose
Public Rater Tier None (Open Access) GET /eval.html, GET /api/campaigns, GET /api/items, POST /api/raters, POST /api/evaluations. Enables friction-free evaluation for research participants.
Admin Researcher Tier X-Admin-PIN header or Authorization: Bearer pin-<token> /api/admin/*, POST /api/suites, POST /api/campaigns, POST /api/upload-audio, DELETE /api/campaigns. Restricts study deletion, raw audio injection, and data exports.

3. Administrative & Creator Endpoints

POST /api/suites Admin PIN Creates a new test prompt suite with paired audio items

Source: run_server.py:796

Accepts suite name and an array of items containing item keys, Khmer text transcripts, and audio asset paths.

POST /api/campaigns Admin PIN Deploys an active study with modular UI canvas configuration

Source: run_server.py:739

Links a test suite and scoring rubric, persisting ui_config_json (card layout, speeds, blind gating, and telephone filter settings).

GET /api/admin/summary?campaign_id={id} Admin PIN Computes consensus scores, MOS with 95% CI, and defect statistics

Source: run_server.py:412

Calculates statistical metrics across all rater evaluations: Mean Opinion Score, standard deviation, 95% Student's t-distribution confidence intervals, and defect frequency counts.

GET /api/admin/export.csv?campaign_id={id} Admin PIN Exports raw evaluation audit ledger as downloadable CSV

Source: run_server.py:550

Streams full tabular evaluation data including item keys, model IDs, rater names, individual rubric scores, timestamps, and acoustic defect tags for thesis paper analysis.

4. Binary Audio Streaming Endpoint

GET /audio/{model_or_folder}/{filename} Public Streams WAV/MP3 files with HTTP 206 Partial Content support

Source: run_server.py:175-220

Inspects request headers for Range: bytes=start-end. Returns HTTP 206 with Content-Range and Accept-Ranges: bytes, enabling waveform scrubbing and fast seeking.
